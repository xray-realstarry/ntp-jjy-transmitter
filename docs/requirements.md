# 要件定義(ドラフト v0.1)

## 1. 目的

WiFi で NTP から取得した時刻をもとに、JJY 互換の疑似標準電波(40kHz / 60kHz)を室内で送信し、
室内の電波時計を時刻合わせできるデバイスのハード・ソフトを開発する。

## 2. 前提・制約

| 項目 | 内容 |
|---|---|
| 対象周波数 | 40kHz / 60kHz をソフトウェアで切替可能 |
| 到達範囲 | 部屋全体(コストと相談しつつ、段階的に拡大) |
| 検証用時計 | フォルミア HT-034RC(40/60kHz 両対応。強制受信では両周波数を走査する) |
| MCU | ESP32 系(第一候補: ESP32-C3) |
| 開発環境 | Arduino-ESP32(PlatformIO 推奨)。JJY エンコーダは純 C++ で分離しホストでテスト |
| 計測器 | テスターあり。オシロは汎用の電子工作用に新規購入予定(§6、docs/bom.md) |
| 電源 | USB 5V |

## 3. 法規

- 日本の微弱無線(322MHz 未満)の条件: 3m 離れた地点で電界強度 500µV/m 以下。
- 設計上、出力は「届く最小限」から調整して上げていく。最大出力は抵抗値とデューティでハード/ソフト両面から制限する。
- 実測が難しいため、拾い用コイル+計測による概算評価の方法を `docs/` に残す。
- **要確認**: 最新の電波法令・総務省告示を実装前に確認する(本ドキュメントは調査済みの断定ではない)。

## 4. 機能要件

- FR1: SNTP で `ntp.nict.jp`、フォールバックに `pool.ntp.org` を使用し時刻同期する。
- FR2: 時刻から JJY の 60 ビットフレーム(分・時・通算日・年・曜日・パリティ・うるう秒予告など)を生成する。仕様は NICT の公開資料に従い、ユニットテストで検証する。
- FR3: 秒の頭で搬送波を低出力へ切り替え、ビット値に応じて 0.8s(0)/ 0.5s(1)/ 0.2s(マーカー)保持する。秒境界の誤差は数 ms 以内。
- FR4: 搬送波 40kHz / 60kHz を LEDC で直接生成する。振幅は約 100% ↔ 約 10% の 2 値(デューティで調整)。
- FR5: 初回は SoftAP キャプティブポータルで WiFi を設定する。以降は Web UI で、周波数切替、送信オン/オフ、スケジュール、出力レベル、状態(最終 NTP 同期、送信中フレーム)を確認・設定できる。
- FR6: 送信モードは「常時」「時間帯指定(例: 時計の自動受信時刻 1〜6 時を含む)」「手動(受信強制用)」を持つ。
- FR7: NTP 取得に失敗しても内部時計で継続(ホールドオーバー)し、定期的に再同期する。長時間の未同期時は送信を止める。
- FR8: 電源投入後、NTP 同期が取れるまで送信しない(誤った時刻を送らない)。

## 5. 非機能要件

- 部品は通販で入手可能なものに限る。試作 1 台の目安は 5,000〜10,000 円。
- 周波数・出力・ピン割り当ては設定可能にし、ハード変更に追従しやすくする。
- 出力制限回路(抵抗・デューティ上限)を外せないようにファームで上限をクランプする。

## 6. ハード構成と検証計画(段階的)

オシロがないため、検証は「時計そのもの」と「PC サウンドカード」を使う。

1. **Stage 0 – 論理確認**: ロジアナで GPIO の秒境界とパルス幅を確認する(LEDC 搬送波は 100kHz 以上のサンプリングが必要)。
2. **Stage 1 – 近接**: フェライトバーコイル+抵抗で、時計をコイルに近づけて受信が成立するか確認する。
3. **Stage 2 – 共振**: 40/60kHz 用の直列コンデンサを入れ、共振で出力を稼ぐ。
4. **Stage 3 – 部屋全体**: 差動(ブリッジ)駆動+大きめのループまたは複数アンテナで、距離を段階的に伸ばす。法規の上限を超えない範囲で。
5. **波形確認(代替)**: 192kHz サンプリング対応のオーディオ入力+拾い用コイルで録音し、PC 上で波形・フレームを確認する。もしくは安価な小型オシロの導入を検討する。

## 7. 未決事項

- HT-034RC の強制受信の操作方法と、走査順・1 周波数あたりの待ち時間(実測で確認)。送信は一度に 1 周波数のみとする。
- MCU の型番確定(C3 / S3 / 無印)。
- 最終的なアンテナ形態(フェライトバー / 空芯ループ)。
- 出力測定手段(小型オシロ導入の可否)。
